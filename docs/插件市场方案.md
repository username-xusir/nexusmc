# NEXMC 插件市场完整方案（GitHub-only）

> 目标：不租服务器、不建网站、不买数据库，只使用 GitHub 公共仓库、GitHub Releases 和免费 CDN，完成 NEXMC 的模组/插件目录、下载、校验、下架和更新。
>
> 本文是方案和验证记录，不是当前版本的已实现功能。

## 1. 结论

可行，但要分两层：

1. **模组目录**：只存元数据、图标和下载地址，NEXMC 下载后放进游戏实例。这一层最简单，现有 PCL 下载内核就能承担。
2. **NEXMC 插件市场**：插件是要在启动器里执行代码的。必须有独立插件进程、权限声明、签名和撤销机制，不能只靠“只允许 GitHub 下载”。

GitHub 作为唯一后台是合理的 MVP 选择：

- 公共仓库免费
- Releases 免费
- GitHub Actions 公共仓库免费
- Raw / jsDelivr 可做索引和图标
- 不需要服务器、数据库和运维

代价是：

- GitHub Raw 在国内可能不稳定
- GitHub 不是大文件 CDN
- 仓库被删、账号被封、DMCA 下架时没有备用后台
- 静态 JSON 不适合复杂搜索和审核后台

## 2. 仓库结构

建议单独建一个公开仓库，例如 `nexusmc-market`，不要让主程序仓库承担市场数据。

```text
nexusmc-market/
  README.md                    给人看的目录（由 Action 生成）
  index.json                   插件索引
  revoked.json                 撤销/下架列表
  schema/
    index.schema.json          索引 JSON Schema
    revoked.schema.json        撤销列表 Schema
  plugins/
    <plugin-id>.json           单个插件详情（可选拆分）
  icons/
    <plugin-id>.png            插件图标
  mods/
    index.json                 模组目录（第二阶段）
  .github/
    workflows/
      validate.yml             校验 JSON、图标、哈希、链接
      render-readme.yml        从 index.json 生成 README
```

客户端只需要读取：

```text
index.json
revoked.json
icons/*
```

插件文件不放在仓库里，放 GitHub Releases：

```text
https://github.com/<owner>/<repo>/releases/download/<tag>/<asset>.nexplugin
```

原因：

- 仓库单文件上限 100 MB
- Release 单文件上限 2 GB
- 大文件放仓库会拖慢 clone
- Release 资源可以单独删除/替换

## 3. 索引协议

完整示例：

- `docs/plugin-market/index.example.json`
- `docs/plugin-market/revoked.example.json`
- `docs/plugin-market/schema/index.schema.json`

核心字段：

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-11-13T12:00:00Z",
  "plugins": [
    {
      "id": "nexmc.example.quick-launch",
      "name": "快速启动",
      "summary": "在 NEXMC 顶部增加一键启动按钮。",
      "icon": "icons/quick-launch.png",
      "author": { "name": "username-xusir", "github": "username-xusir" },
      "license": "MIT",
      "apiVersion": 1,
      "latest": "1.0.0",
      "versions": [
        {
          "version": "1.0.0",
          "publishedAt": "2026-11-13T12:00:00Z",
          "download": "https://github.com/.../releases/download/.../quick-launch.nexplugin",
          "sha256": "64位小写十六进制",
          "size": 24576,
          "minHost": "1.0.10",
          "maxHost": null,
          "permissions": ["instance.read", "process.start"],
          "dependencies": []
        }
      ]
    }
  ]
}
```

约束：

- `id` 必须是小写命名空间格式，例如 `作者.插件名`
- 同一 `id` 不能重复
- `latest` 必须存在于 `versions`
- `sha256` 必须是 64 位小写十六进制
- `download` 只接受 GitHub Release 地址
- `icon` 必须是仓库内相对路径，不能包含 `..`
- `permissions` 必须是白名单枚举
- 一个插件最多保留 50 个版本

## 4. 客户端读取流程

```text
启动市场页
  → 读取本地缓存 index.json
  → 后台请求 index.json
      1) raw.githubusercontent.com/<owner>/<repo>/main/index.json
      2) cdn.jsdelivr.net/gh/<owner>/<repo>@main/index.json
      3) 本地缓存
  → 校验 schemaVersion / JSON / id / 版本 / 哈希格式
  → 异步加载图标（同样的 raw → jsDelivr → 本地缓存）
  → 渲染列表
```

缓存位置：

```text
%LocalAppData%\NEXMC\Market\index.json
%LocalAppData%\NEXMC\Market\icons\<hash>.img
```

刷新策略：

- 页面打开时先用缓存，网络请求成功后再替换
- 手动刷新强制绕过缓存
- `revoked.json` 每次启动都检查；失败时保留上次结果
- 索引请求失败不影响已安装插件

## 5. 安装流程

```text
选择插件/版本
  → 检查插件 minHost/maxHost
  → 解析 dependencies
  → 展示权限清单
  → 用户确认
  → 下载到临时文件
  → 校验 SHA-256 和大小
  → 校验插件包 manifest
  → 解压到版本目录
  → 写入安装记录
  → 启用插件
```

目录：

```text
%LocalAppData%\NEXMC\Plugins\<id>\<version>\
%LocalAppData%\NEXMC\Plugins\<id>\state.json
%LocalAppData%\NEXMC\Market\downloads\<sha256>.tmp
```

失败处理：

- 哈希不匹配：删除临时文件，不安装
- 包结构不合法：删除临时目录
- 磁盘满/权限错误：保留旧版本
- 更新失败：回滚到旧版本
- 下载中断：保留 `.tmp`，下次可断点续传（由 PCL 内核处理）

## 6. PCL 下载内核怎么接入

现有 `Nexmc.Kernel` 已经有通用的 `LoaderDownload` / `NetFile` 能力，可以下载任意 HTTP 地址。需要补一个门面方法，例如：

```text
KernelFacade.DownloadUrl(url, destination, expectedSha256, report, cancellation)
```

职责：

- 调用 PCL 多线程下载
- 支持重试、限速、断点续传
- 进度回传给市场页
- 下载完成后由客户端再做 SHA-256 校验

注意：

- PCL 的 BMCLAPI 线路只镜像游戏/模组资源，**不会自动镜像任意 GitHub 仓库**
- 所以“GitHub 慢就转 PCL 线路”只对 PCL 认识的资源有效
- 对 GitHub Release，PCL 只能提供多线程和重试，不能变出可用镜像
- 如果以后加镜像，镜像地址必须带同一个 SHA-256

## 7. 下架与撤销

只编辑 `index.json` 只能让新用户看不到，不能处理已安装用户。

实际需要两个文件：

```text
index.json      正常目录
revoked.json    撤销列表
```

`revoked.json` 示例：

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-11-13T12:00:00Z",
  "entries": [
    {
      "id": "nexmc.example.bad-plugin",
      "version": "1.0.0",
      "sha256": "...",
      "severity": "block",
      "reason": "包含未授权的文件删除行为"
    }
  ]
}
```

客户端行为：

- `severity=block`：禁用插件，提示用户，不再启动
- `severity=warn`：标记风险，允许用户手动继续
- 只匹配 `id + version + sha256`，避免误伤同 ID 的其他版本
- 每次启动检查；网络失败时保留上次撤销结果

这仍然不是“彻底删除”：

- 已经下载的代码可能已经运行过
- 用户可能离线
- 仓库的 Git 历史仍然保留旧提交
- fork 可能保留旧文件

所以撤销是“止损”，不是“召回”。

## 8. 只允许 GitHub：边界在哪

索引和图标：

- `raw.githubusercontent.com`
- `cdn.jsdelivr.net`

插件包：

- `github.com/<owner>/<repo>/releases/download/...`
- 运行时允许 GitHub 的 302 目标：
  - `objects.githubusercontent.com`
  - `release-assets.githubusercontent.com`

校验器会拒绝：

- 非 GitHub Release 的下载地址
- `http://` 地址
- 带 `..` 的图标路径
- 非 HTTPS 地址

但这只解决“来源统一”，不解决“代码可信”。任何人都能注册 GitHub 账号上传恶意插件。

## 9. 真正的安全边界

### 模组

模组最终由 Minecraft 执行。即使 NEXMC 只负责下载，也要：

- 校验哈希
- 审核来源
- 检查许可证
- 不自动启用陌生模组

### NEXMC 插件

不能把插件 DLL 直接 `Assembly.Load` 进主进程。推荐：

```text
NEXMC.exe
  ↕ 命名管道 / JSON-RPC
NEXMC.PluginHost.exe
  ↕ 每个插件独立进程
插件 DLL
```

插件宿主负责：

- 每个插件独立进程，崩溃不影响主界面
- 权限声明：网络、实例读、实例写、文件读、文件写、启动进程
- 超时和资源限制
- 插件 API 版本检查
- 只允许宿主提供的 API，不允许直接操作 WPF 窗口
- UI 扩展用声明式命令/菜单，不加载插件的任意 WPF 控件

这一步是“插件市场”和“下载目录”的分界线。

## 10. GitHub Actions 自动校验

公共仓库免费，建议两个 Action：

### validate.yml

```text
读取 index.json
校验 JSON Schema
检查 id 唯一
检查 latest 在 versions 中
检查 sha256 格式
检查 download 是 GitHub Release
检查 icon 存在且小于 200 KB
检查 version 数量上限
```

### render-readme.yml

```text
从 index.json 生成 README 表格
列出插件名、作者、版本、图标、许可证
避免手工维护两份数据
```

本地验证脚本已经放在：

```text
docs/plugin-market/validate-registry.mjs
```

## 11. 分阶段落地

### 阶段 0：仓库和协议

交付：

- 市场仓库
- `index.json` / `revoked.json`
- JSON Schema
- 校验脚本
- GitHub Actions

不接客户端，先保证数据格式稳定。

### 阶段 1：只读市场页

交付：

- NEXMC 新页面「插件市场」
- 读取 index、显示图标、搜索、分类
- 不下载、不执行
- 网络失败时显示缓存

验收：

- raw 失败自动切 jsDelivr
- 两边都失败时显示缓存
- 图标失败显示占位，不阻塞列表

### 阶段 2：模组/资源下载

交付：

- 下载插件包/模组文件
- SHA-256 校验
- 安装到实例
- 失败回滚

这一阶段不执行插件代码，风险最低。

### 阶段 3：插件运行时

交付：

- `NEXMC.PluginHost.exe`
- 权限确认页
- 独立进程、崩溃隔离
- 示例插件
- 禁用/卸载

验收：

- 插件崩溃不影响主界面
- 未授权 API 调用被拒绝
- 插件无法直接读宿主任意文件

### 阶段 4：签名和撤销

交付：

- 发布者签名
- 客户端公钥
- `revoked.json` 强制检查
- 自动更新和回滚

这一阶段才适合开放更多作者。

## 14. 关键限制

1. **GitHub 不是 CDN**：Raw 可能被墙，Release 也可能慢。
2. **PCL 不能代理任意 GitHub 文件**：它只能加速你提供的 URL。
3. **只允许 GitHub 不等于安全**：恶意作者仍可上传。
4. **改 index 不等于下架**：必须配合 `revoked.json`。
5. **插件执行代码必须隔离**：不能在主进程直接加载。
6. **签名不能省**：否则索引或 Release 被替换时客户端无法发现。

## 15. 建议的下一步

如果按这个方案做，第一步不是写插件市场页面，而是：

1. 建 `nexusmc-market` 仓库
2. 放入 `index.json`、`revoked.json`、schema、图标
3. 跑通 GitHub Actions 校验
4. 再让 NEXMC 只读目录并显示图标
5. 最后才做插件运行时

这样最省钱，也最容易在每一步验证。
