# NEXMC 1.1.3 更新说明

1.1.3 修复夸克网盘大文件下载到约 9% 时返回 `412 Precondition Failed` 的问题，并保留 1.1.2 的更新检查修复。

## 问题是什么

下载夸克整合包时，任务在 9% 左右失败，错误是：

```text
错误码 PreconditionFailed (412)
```

CDN 返回的响应头：

```text
Auth-Result: 1/-/403
Ks-Deny-Reason: third-party-remote-auth|resp-status:403-match-rule-forbidden
```

这不是链接过期。夸克直链的签名和取链时的会话绑定；`file/download` 响应会刷新 `__puus` 等 Cookie。旧代码只提取了 `__pugs`，下载时继续使用旧的 `__puus`，所以前面几段能下，后面就被 CDN 拒绝。

## 修复方式

- 从 `file/download` 响应读取**全部** `Set-Cookie`，不再只提取 `__pugs`；
- 用响应里的新值覆盖旧值，再交给快速分片路径和 PCL2 内核；
- Cookie 合并抽到 `NetdiskCookieHeader`，并加入回归测试；
- 快速分片和 PCL2 回退共用同一份刷新后的 Cookie。

## 实际验证

- 单元测试：79/79 通过。
- 修复前：同一平台首个 Range 请求就返回 412。
- 修复后：16 / 64 / 128 路并发 Range 请求全部返回 206。
- 174.1MB 整合包通过快速分片路径完整下载：182,563,002 字节，ZIP 97 个条目，无 412。
- 1.1.2 的更新检查缓存仍然有效：10 分钟内重复启动不重复请求 GitHub；手动检查会强制刷新。

## 保留的 1.1.2 修复

- 更新检查增加 10 分钟本地缓存：`%LOCALAPPDATA%\NEXMC\update-cache.json`。
- 使用 `ETag` 条件请求，GitHub 返回 304 时复用缓存。
- 同时处理 403 / 429，提示具体的配额恢复时间。
- 手动“检查更新”不受缓存限制。

## 还没做好的

- 百度、123、115、迅雷、蓝奏等还没有自动取链。
- 登录后的真实大文件下载仍需要有效账号；本次夸克验证使用的是本机已保存的登录 Cookie。
- 安装包没有代码签名，Windows 可能显示“未知发布者”。
