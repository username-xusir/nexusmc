# NEXMC 1.1.2 更新说明

1.1.2 只处理自动更新检查的 GitHub 限流问题，网盘、云析参考部分和界面布局保持不变。

## 为什么会看到“GitHub 暂时限制了更新查询”

NEXMC 的更新检查使用 GitHub 公开 API：

```text
https://api.github.com/repos/username-xusir/nexusmc/releases/latest
```

GitHub 对未登录请求按公网 IP 限流，通常是 60 次/小时。之前每次启动 NEXMC 都会自动检查一次更新；发布 1.1.1 时反复启动安装包做验证，配额被用完，GitHub 返回 `403`，界面就显示了那条提示。

这不是 Release 丢失，也不是 1.1.1 安装包有问题。

## 这次改了什么

- 自动检查增加 **10 分钟本地缓存**，缓存文件在 `%LOCALAPPDATA%\NEXMC\update-cache.json`。
- 使用 GitHub 的 `ETag` 做条件请求；返回 `304 Not Modified` 时直接复用上次结果。
- 同时处理 `403 Forbidden` 和 `429 Too Many Requests`。
- 优先读取 `Retry-After`，其次读取 `X-RateLimit-Reset`，提示具体的恢复时间，而不是只说“稍后再试”。
- 手动点击“检查更新”仍然强制查询最新 Release，不受 10 分钟缓存限制。
- 请求头加入 `X-GitHub-Api-Version: 2022-11-28`。

## 实际验证

- 单元测试：77/77 通过（新增 403 和 429 两条限流提示测试）。
- 第一次启动：生成 `update-cache.json`，缓存 7,549 字节的 Release JSON，并记录 ETag。
- 10 分钟内第二次启动：缓存时间戳保持不变，GitHub API 剩余额度没有减少，说明没有重复请求。
- 手动点击“检查更新”：缓存时间戳更新，界面显示“当前已是最新版本 1.1.2”。
- 自动检查和手动检查分别走缓存与强制刷新两条路径。

## 还没做好的

- 缓存只保留最新 Release 的 JSON，不缓存安装包本身。
- 缓存过期后如果 GitHub 仍然限流，会显示具体恢复时间，但不会绕过限制。
- 安装包没有代码签名，Windows 可能显示“未知发布者”。
